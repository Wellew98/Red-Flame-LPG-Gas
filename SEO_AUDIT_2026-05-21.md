### What's wrong

Every one of the 10 HTML files in `Red Flame Gas Supply/` is **truncated** — each one ends abruptly mid-content with no `</footer>`, no `</body>`, no `</html>`.

Verified three ways: line counts, a grep for closing tags (`</html>`, `</body>`, `</footer>` all return **0 across all 10 files**), and reading the tail of each file. Examples:

- `index.html` (729 lines) — cuts off mid-FAQ: *"...sign the job off with a"*
- `woodstock.html` (428 lines) — cuts off mid-footer: *`<a href="...facebook..." target="_blank"`*
- `higgovale.html` (297 lines) — cuts off at the footer Contact heading
- The other 7 — all cut off in the footer region

### It's already live on the suburb pages

I fetched the live site to check. **The live suburb pages are serving truncated HTML** — verified directly on `redflamegas.co.za/woodstock` and `/higgovale`, which both end at the exact same point as the local files, mid-element. The other 7 suburb pages were deployed in the same push and are near-certainly identical. The live suburb pages are missing:

- the footer **Contact column** (phone / WhatsApp / email / Facebook links)
- the **floating WhatsApp button**
- the **mobile sticky call bar**
- closing `</footer></body></html>`

The **homepage is the exception** — the *live* `index.html` is still the older, intact, complete version. The *local* `index.html` is truncated. So the broken homepage has **not** been deployed yet.

### Impact — serious but not a site-down emergency

Browsers auto-close missing tags, so the pages still render and customers aren't hitting a blank screen. But the 9 suburb landing pages — the core of the local-SEO strategy — are each missing **both** always-visible mobile conversion elements (floating WhatsApp + sticky call bar) and part of the footer. For a business whose stated problem is converting impressions into leads, losing the persistent mobile CTA on every suburb page is a real, ongoing leak.

### Cause

The files were truncated during bulk multi-file edits in recent sessions (GA4 install across 10 files, schema rebuild across 9). This is a known failure mode — `HANDOFF_CONTEXT.md` literally carries the lesson *"Don't trust large Edit operations on long files without a tail-integrity check."* It wasn't guarded against. This is a tooling/process failure on my side, not anything you did.

### Do not deploy until repaired

Specifically: **do not push the local `index.html`** — that would break the one page that currently still works.

### Recovery plan

1. **Rebuild all 10 files** to complete, valid pages: re-append the missing footer + floating-WhatsApp + sticky-call-bar + closing tags. The tail markup is near-identical across pages, so this is reconstructable. For `index.html`, the new "8-points" content (see §1) is merged with the intact tail copied from the live homepage.
2. **Validate** each file ends with `</html>` and contains the footer + both conversion elements.
3. **Redeploy all 10 together**, then smoke-test (view source → confirm each ends `</html>`; check the floating WhatsApp + sticky bar appear on mobile).
4. There is no clean backup: the local files and the GitHub repo both hold truncated versions, and the live suburb pages are truncated too. The live **homepage** is the only complete reference, which is enough to reconstruct the shared tail.

**Status: files repaired and verified locally on 2026-05-21. P0 is now just the deploy + smoke test in §2.**
